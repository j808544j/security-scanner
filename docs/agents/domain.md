# Domain docs

Before exploring the codebase, read the root `GLOSSARY.md` and any architecture decision records in `docs/adr/` relevant to the work. If those files are absent, proceed.

Use glossary terms consistently in specs, tickets, and tests. When a proposal conflicts with an existing decision, cite the relevant ADR and explain the conflict.

Use `/domain-modeling` to record agreed terms in `GLOSSARY.md` and significant decisions in `docs/adr/` as they arise.
